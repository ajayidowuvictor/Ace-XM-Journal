# Architecture

## Layers
1. `app/`: screens and routes only (Expo Router).
2. `src/ui/`: design tokens and reusable components.
3. `src/features/<feature>/`: components, hooks and logic per feature.
4. `src/db/`: SQLite via expo-sqlite, numbered migrations, repository functions. The only code that writes SQL.
5. `src/lib/`: date and time-zone helpers, streak and review calculations, export.

## Data model (local first)
tasks, categories, journal_entries, tags, entry_tags, mood_records, habits, habit_completions, goals, milestones, task_goal_links, reviews, settings.
Every row has a UUID, `created_at`, `updated_at` and `deleted_at`, so cloud sync can be added later without a rewrite.

## Dates
Day-based records store a local calendar date string (`YYYY-MM-DD`). Moments store UTC timestamps. This avoids time-zone and date-boundary bugs in habits and the calendar.

## Privacy and security
Local-only first release. Journal database encrypted on the device. No secrets in the repository; only public keys in the app. If cloud sync is added (Phase 7): Supabase Auth and row-level security on every table.
